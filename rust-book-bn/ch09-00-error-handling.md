# Error Handling

সফটওয়্যারে error হল একটি অনিবার্য সত্য, তাই Rust-এ এমন পরিস্থিতি সামাল দেওয়ার জন্য বেশ কিছু feature আছে যেখানে কিছু ভুল হতে পারে। অনেক ক্ষেত্রে Rust তোমাকে একটি error-এর সম্ভাবনা স্বীকার করতে এবং কোনো একটি পদক্ষেপ নিতে বাধ্য করে, নাহলে তোমার code compile হবে না। এই শর্তের কারণে তোমার program আরও শক্তিশালী হয়, কারণ এতে নিশ্চিত হয় যে তুমি production-এ code deploy করার আগেই error খুঁজে পাবে এবং সেগুলো যথাযথভাবে handle করবে!

Rust error-কে দুটি প্রধান শ্রেণীতে ভাগ করে: recoverable এবং unrecoverable error। একটি _recoverable error_-এর ক্ষেত্রে, যেমন _file not found_ error, আমরা সম্ভবত শুধু সমস্যাটি user-কে জানাতে চাই এবং কাজটি আবার চেষ্টা করতে চাই। _Unrecoverable error_ সবসময় bug-এর লক্ষণ, যেমন একটি array-এর শেষের বাইরের কোনো অবস্থান অ্যাক্সেস করার চেষ্টা, তাই এ ক্ষেত্রে আমরা program-টি সাথে সাথে থামিয়ে দিতে চাই।

বেশিরভাগ language এই দুই ধরনের error-এর মধ্যে পার্থক্য করে না এবং exception-এর মতো mechanism ব্যবহার করে দুটোকেই একইভাবে handle করে। Rust-এ কোনো exception নেই। এর বদলে, recoverable error-এর জন্য আছে `Result<T, E>` type এবং যখন program একটি unrecoverable error-এর মুখোমুখি হয় তখন execution থামিয়ে দেওয়ার জন্য আছে `panic!` macro। এই অধ্যায়ে আমরা প্রথমে `panic!` call করা নিয়ে আলোচনা করব, তারপর `Result<T, E>` value return করা নিয়ে কথা বলব। এছাড়া, একটি error থেকে recover করার চেষ্টা করবে নাকি execution থামিয়ে দেবে—এই সিদ্ধান্ত নেওয়ার সময় কী কী বিবেচনা করতে হবে তাও আমরা দেখব।
